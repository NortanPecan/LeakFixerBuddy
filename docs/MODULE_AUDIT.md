## 1. GYM Module

### Сценарий сохранения (основной юзер-флоу)

1. **Создание периода тренировок:**
   - Жмём "+" → открывается wizard
   - Выбираем тип тренировок (на силу/выносливость/кастом)
   - Выбираем схему (сплит/фулбоди/PPL/верх-низ/кастом)
   - Настраиваем дни и группы мышц
   - Подтверждаем → создаётся период

2. **Добавление упражнения в тренировку:**
   - Открываем тренировку → "Добавить упражнение"
   - Выбираем из библиотеки или вводим имя
   - Упражнение создаётся с дефолтными сетами

3. **Заполнение весов/повторений:**
   - Вводим вес и повторы в инпуты
   - Автосохранение с debounce

4. **Завершение тренировки:**
   - Жмём "Завершить" → открывается диалог оценки
   - Оцениваем упражнения (легко/норм/тяжело)
   - Подтверждаем → статус = completed

### Таблицы Supabase (Prisma models)

| Таблица | Назначение | API endpoint |
|---------|------------|--------------|
| `gym_periods` | Периоды тренировок | `/api/gym` |
| `gym_cycles` | Циклы внутри периода | `/api/gym/workouts` |
| `gym_workouts` | Отдельные тренировки | `/api/gym/workouts` |
| `gym_workout_templates` | Шаблоны дней | `/api/gym/templates` |
| `gym_workout_template_exercises` | Упражнения в шаблонах | `/api/gym/templates` |
| `gym_exercises` | Упражнения в тренировках | `/api/gym/exercises` |
| `gym_exercise_sets` | Подходы в упражнениях | `/api/gym/exercises/sets` |
| `gym_exercise_templates` | Библиотека упражнений | `/api/gym/templates` |

### Результат проверки сохранения

| Действие | Сохраняется | Примечание |
|----------|-------------|------------|
| Создание периода | ✅ Да | `db.gymPeriod.create()` |
| Создание тренировки | ✅ Да | `db.gymWorkout.create()` |
| Создание упражнения | ✅ Да | `db.gymExercise.create()` |
| Добавление сета | ✅ Да | `db.gymExerciseSet.create()` |
| Обновление веса/повторов | ✅ Да | `db.gymExerciseSet.update()` |
| Завершение тренировки | ✅ Да | `db.gymWorkout.update({ completed: true })` |
| Обновление nextWeight | ✅ Да | `db.gymExercise.update()` |

**Вердикт:** Сохранение работает корректно. Данные уходят в Supabase через Prisma.

### Юзабельность

**Что мешает пользоваться:**
1. Очень большой экран (4000+ строк) — сложно ориентироваться
2. Много вложенных диалогов (wizard → 4 шага)
3. Drag & drop для расписания неочевиден
4. Нет индикации загрузки на некоторых операциях

### Баги

| ID | Описание | Критичность |
|----|----------|-------------|
| G-1 | muscleGroups парсится из строки каждый раз (JSON.parse в рантайме) | Низкая |
| G-2 | Нет обработки ошибок при неудачном сохранении сета | Средняя |
| G-3 | Debounce может потерять данные при быстром переключении | Средняя |

### Улучшения UX/UI

1. Разбить GymScreen на вкладки (Сегодня / Календарь / Библиотека)
2. Добавить скелетоны при загрузке
3. Показывать toast при успешном сохранении
4. Упростить wizard до 2 шагов

### Технический долг / Рефакторинг

## 5. Tasks / Chains Module

### Сценарий сохранения (основной юзер-флоу)

1. **Создание одиночной задачи:**
   - Жмём "Дело" → открывается CreateTaskScreen
   - Заполняем: текст, дата, время, зона
   - Подтверждаем → создаётся task без chainId

2. **Создание цепочки:**
   - Жмём "Цепочка" → открывается CreateChainScreen

   - Создаётся chain + task с chainId

   - Жмём на круг → PATCH с status: 'done'

   - Для цепочки: открывается диалог "Что дальше?"

4. **Добавление шага в цепочку:**
   - После завершения шага → диалог
   - Вводим текст нового шага → POST task с chainId
   - Автоинкремент order
