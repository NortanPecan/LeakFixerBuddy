# Leaks Module Context

Обновлено: 2026-03-19

## Зачем нужен отдельный модуль

`Leaks` не стоит размазывать по всему приложению сразу.

Причины:
- так мы не запутаем текущий продукт;
- можно проверить реальную ценность отдельного leak-flow;
- модуль потом можно либо постепенно встроить в ядро продукта, либо вынести в отдельное приложение.

## Главная продуктовая идея

LeakFixer должен не просто хранить трекеры.

Он должен:
1. помогать замечать скрытые проблемы и повторяющиеся паттерны;
2. формулировать конкретные лики;
3. превращать их в выполнимые действия;
4. учиться на том, что реально сработало у человека.

Короткая формулировка:

> LeakFixer помогает превращать любые внутренние проблемы, срывы и слабые места в конкретный, адаптивный план действий с отслеживанием результата.

## Роль Wellbeing

`Wellbeing` не конфликтует с `Leaks`.

Лучшее разделение:
- `Wellbeing` = диагностический слой;
- `Leaks` = слой формулировки проблемы и вмешательства;
- `AI` = связывает сигналы, объясняет причины, предлагает варианты;
- `Actions` = ритуалы, задачи, навыки, качества, челленджи.

Коротко:

- Wellbeing замечает.
- Leaks формулируют.
- AI объясняет.
- Система действий исправляет.

## Как должен работать продукт

Нужен гибридный подход, а не только автопоиск и не только ручной ввод.

### Passive detection

Приложение само замечает подозрительные сигналы:
- повторяющиеся просадки;
- связи между состоянием и поведением;
- недельные и месячные тренды.

### Active capture

Пользователь сам записывает:
- лик;
- сбой;
- мысль;
- паттерн, который заметил;
- то, что хочет исправить позже.

### Leak engine

AI объединяет:
- данные из трекеров;
- wellbeing;
- checkins;
- заметки;
- ручные лики;
- прошлые удачные и неудачные решения.

## Что решили для v1

Первый вертикальный срез делаем без новой таблицы под полноценный leak inbox.

Используем уже существующий фундамент:
- `notes` как быстрый inbox для ручных ликов;
- `weekly-report` как источник автоматически найденных сигналов;
- `user_ai_patterns` как историю AI-паттернов и того, что сработало.

Структура модуля v1:
- `Inbox`
  - быстрый capture;
  - сохранение в `notes` с `zone=leaks`;
  - возможность позже разобрать с ИИ;
- `Signals`
  - leak hints из weekly report;
  - переход к AI-разбору;
- `Patterns`
  - накопленные AI-паттерны;
  - сколько раз анализировали;
  - что сработало.

## Что важно не делать сразу

Пока не размазывать новую идею по всему приложению:
- не перестраивать весь home;
- не связывать `Leaks` с finance;
- не переписывать journey вокруг leaks;
- не делать голос;
- не делать прогнозы как отдельный большой слой;
- не тащить адаптацию книг и курсов раньше времени.

## Следующий продуктовый рост после v1

### P0
- отдельный модуль `Leaks`;
- быстрый capture;
- signals из данных;
- AI-разбор;
- история паттернов;
- feedback loop по решениям.

### P1
- три режима решения:
  - минимум;
  - база;
  - максимум;
- конвертация в ритуалы, задачи, навыки, качества;
- связь с контекстом: еда, вода, сон, тренировки, настроение, работа.

### P2
- обучение на пользовательских решениях;
- AI как интерфейс управления приложением;
- прогнозы;
- адаптация книг, курсов, видео;
- голос.
