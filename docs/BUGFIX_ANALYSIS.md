## ФИНАНСЫ

### 1. Баг: Создалось 2 одинаковых счёта

**Анализ:**
- В FinanceScreen.tsx (строка 158-195) `handleCreateAccount` не проверяет дубликаты
- API `/api/accounts` (POST) тоже не имеет проверки на уникальность имени счёта
- Возможна ситуация: пользователь дважды кликнул по кнопке "Создать"

**Предложение:**
1. Добавить проверку на дубликаты по имени + типу на фронте (disable кнопки при совпадении)
2. Добавить уникальный индекс в БД: `(userId, name, type)`
3. Добавить debounce на кнопку создания (500ms)

**Приоритет:** Средний

**Анализ:**
- Сейчас: пользователь вводит `amount` (+/-)

### 6. Дела создаются на предыдущее число

**Анализ:**
- CreateTaskScreen.tsx строка 25:
  ```js
  const [date, setDate] = useState(() => new Date().toISOString().split('T')[0])
  ```
- API tasks/route.ts строка 88:
  ```js
  date: date ? new Date(date) : null
  ```
- Проблема: `new Date('2025-03-14')` в JS создаёт дату в UTC 00:00, что может быть предыдущим днём в локальном времени!

**Предложение:**
1. Использовать `new Date(date + 'T12:00:00')` для создания полуденной даты
2. Или передавать строку как есть, без конвертации в Date

**Приоритет:** Критичный

### 7. Выполнить дело не работает

**Анализ:**
- TasksScreen.tsx `handleToggleTask` (строки 187-212)
- API PATCH отправляет `status: 'done'`
- Но SortableTaskCard (строки 821-839) вызывает `onToggle(task, false)` всегда!
  - Это баг: всегда передаётся `false`, поэтому дело всегда "невыполнено"

**Предложение:**
1. Исправить SortableTaskCard:
   ```js
   onClick={() => onToggle(task, task.status !== 'done')}  // toggle логика
   ```
2. Или передать правильное значение completed

**Приоритет:** Критичный
